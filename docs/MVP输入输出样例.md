# MVP 输入输出样例

日期：2026-10-26。用途：M02 的需求样例，供后续模型接入和测试使用。这是预期行为，不代表当前页面已经实现全部能力。

## 首版支持什么

- 类型：复用页面现有选项。
- 最长时长：统一换算成分钟，程序严格检查。
- 排除类型或电影：用于本次选片。
- 心情：轻松、治愈、烧脑等作为偏好，不能保证每个人的观看感受。
- 年代：沿用已有页面选项。
- 本次调整：补充条件、换一组、重新开始。

评分要求、地区播放保证、复杂相似片检索等暂不承诺。没有要求的条件保持空，不代替用户编造偏好。

## 用这些例子核对理解结果

| 编号 | 用户怎么说/怎么操作 | 系统应理解成什么 | 下一步应该做什么 |
|---|---|---|---|
| E01 | 不输入，直接看电影 | 没有额外要求 | 查真实目录，返回最多3部 |
| E02 | 想看轻松的喜剧，两个小时以内，不要恐怖片 | 喜剧；最多120分钟；排除恐怖；偏好轻松 | 展示采用条件，再查真实目录；轻松标为偏好 |
| E03 | 想看恐怖片，但不要恐怖片 | 想看和排除发生矛盾 | 先问“这次要看恐怖片，还是排除恐怖片？”；选择后再查询 |
| E04 | 豆瓣9分以上的科幻片 | 想看科幻；还要求评分≥9，但本轮无评分数据 | 明确提示评分条件无法执行；用户确认仅按科幻继续后再查询，不能把评分要求当作已满足 |
| E05 | 在E02后说“改成90分钟以内” | 喜剧、排除恐怖、轻松继续保留；上限改成90分钟 | 按更新后的条件重新查询 |
| E06 | 在E02后说“换一组”或点击换组 | 条件不变；排除本次已经展示的影片 | 返回其他合格影片；没有剩余结果就说明情况 |
| E07 | 今天不想看爱情片 | 本次排除爱情 | 排除参与本次请求；不保存为长期偏好 |
| E08 | 点击“重新开始” | 清除当前筛选、澄清和换组/临时排除状态 | 回到无条件探索；片单与比较保留，清空片单继续使用独立按钮 |
| E09 | 按当前要求找不到电影 | 没有合格候选 | 明确说明无结果，建议用户修改条件；不自行放宽或补造电影 |

## 需要统一的简单规则

1. 类型、时长、年代、明确排除交给程序严格执行；模型负责理解表达。
2. 补充要求只更新提到的条件，其他条件保留；同次文字和点选矛盾先确认。
3. 每次最多提出两个影响选片的问题；一次确认后可继续，始终允许修改原输入。
4. 只保存当前会话上下文，刷新清空可以接受；不接长期记忆。
5. 有一部就返回一部，没有就返回空；来源链接和电影来自真实目录。
6. 当前模型没有接入；后续实现时必须区分规则理解与模型理解，不能只修改显示文字。

## 开发接续

样例确定后，对照 `scripts/s0_contracts.py` 确认字段和样例响应：类型对应 `genres`，分钟对应 `max_runtime_minutes`，排除对应 `exclude_genres` / `exclude_movie_ids`，心情对应 `moods`，年代对应 `era`。冲突与未支持项沿用 `conflicts` / `unhandled`，确认沿用 `needs_clarification`。
