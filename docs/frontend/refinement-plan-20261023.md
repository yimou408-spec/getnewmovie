# 选片体验改进方案（2026-10-23）

本轮目标是让不了解片名的用户先点选、再看候选，并能方便地回到条件继续调整。保留 React、Radix、现有真实片库和证据契约，不以视觉改动暗示评分或多源能力已实现。

## 视觉与信息层级

- 颜色沿用现有六个角色：浅灰背景 `#f5f6f8`、白色内容面、深蓝文字 `#141b25`、灰蓝次要文字 `#586575`、琥珀操作色 `#86531c`、边界 `#dce1e8`；系统深色对应现有 tokens。警告保留语义色。
- 标题使用系统中文无衬线字族，首屏 42–56px、区块 20–24px；正文 15–16px、辅助信息 12–13px。数字使用等宽数字，避免把正文缩小来塞入布局。
- 桌面主区充分使用可用宽度，紧凑横向首屏；六个场景在宽屏横排六列，中等宽度三列两行。点选表单按心情、类型、时长组织，次要条件在同一区域横向排列。文字补充放在点选条件之后。
- 候选采用三列海报卡片，明确区分片名、事实、匹配推断和原始证据。海报保留完整比例；无法加载时保留真实失败提示与重试。
- 手机场景采用两列、条件单列、电影单列；遵循系统明暗主题，不增加独立主题开关。

## 功能与验收约定

1. 已选条件提供单独移除按钮，移除后保留其他选择；下一次请求必须反映改动。
2. 结果区可返回修改条件，恢复键盘焦点，保留当前候选与选择，不发起隐式请求。
3. 关键数据边界始终可见；重复的逐项说明可以折叠，但不得把未知评分、单来源和地区限制伪装为已验证。
4. 现有按钮、自然语言澄清、片单、比较、证据、错误恢复及取消流程继续回归。新增交互先补失败测试再实现。
5. 本地 Chrome 和云端 Chromium 验收分别记录。手机为浏览器设备模拟，不冒充实体手机或 Safari 验收。

## 实施前自检

缩短氛围区后仍保留品牌识别；不靠新增装饰色、虚构分数或样例海报制造丰富度。全部选择控件保持至少 44px 触控目标。辅助信息可展开，核心数据状态与失败提示不隐藏。主要风险是长片名、长条件与手机布局，需要在四种视口/主题组合里实测。
