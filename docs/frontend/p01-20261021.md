## P01：已实现的行为与契约边界

1. 请求层同时保留调用者取消信号和 45 秒等待上限；清理监听器与计时器。主动取消与超时分别提示，不自动重复请求。取消只停止页面等待，不保证上游任务已停止。
2. 422 提示修改输入；未配置状态不提供无效重试；429、503、504 保留受控提示及请求编号，尊重服务端 `retryable: false`。网络失败、非 JSON 错误页和无效成功响应均有明确状态，不直接展示代理 HTML。
3. 推荐请求取消后可重新提交，旧请求晚到不能覆盖新结果；切换页面时取消等待。再次选片失败或取消时仍可查看上一批结果。影片详情和比较请求也传递 TanStack Query 的取消信号。
4. `/health` 增加可选 `capabilities`，由 Pydantic 导出 JSON Schema、OpenAPI 和 TypeScript。`metadata` 为真，其余评分、影评、自然语言、长期记忆、本地渠道为假。前端验证响应后展示；旧响应缺少该字段时显示“待确认”，未知服务身份不显示为已接入。
5. 能力声明只表示服务已实现对应接口，不表示上游此刻可用或推荐质量合格。Apple 影片资料、美国内容分级、口碑评分和本地观看渠道分别处理。

`capabilities` 是对当前接口的增量提案，需 Y00 / Y02 与主审复核；本次未宣称未来多源、会话、证据与记忆契约已冻结。未手改生成文件，生成链为：
