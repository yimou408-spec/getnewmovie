## 本次实现

自然语言是可选主入口，零输入、场景和点选继续可用。填写文字时，前端将原文交给真实服务的规则解析器；服务把类型、心情、时长上限、年代、同行情境及排除类型转为实际约束。类型、时长、年代、排除身份由代码过滤，未知时长不进入时长限定结果；心情是词法启发式软偏好。界面回显实际采用的硬条件、软偏好及没有执行的要求。

文字与点选冲突时，必须选择以哪组条件为准。评分、导演、时长区间等暂不支持的表达先列出，请用户确认仅按识别出的条件继续；内部矛盾要求修改文字，不能直接确认。澄清响应不查片库、不返回候选或证据，界面不展示电影卡。确认答案绑定服务端匿名会话、澄清编号和原请求；编辑、切换选片方式或离开页面使旧答案失效。

连续提交有同步请求锁；取消和页面切换会终止本页面等待，晚到的旧响应不能覆盖新结果。网络错误重试保留同一份答案，取消确认后仍可继续；换组保留已经确认的条件并增加影片排除。会话过期提示重新提交，不能复用旧答案。取消不承诺已停止上游工作。

## 接口增量（待共同契约确认）

- `POST /sessions`：返回服务端随机匿名 `session_id` 和 1800 秒有效期。进程内最多 256 个会话，满额淘汰最早会话；重启后过期，不是账号或长期记忆。
- `POST /recommendations`：新增 `input_source`，默认 `structured` 兼容原路径；`natural_language` 要求服务端会话。新增 `clarification: {clarification_id, answers: [{question_id, option}]}`。答案必须完整且来自当前选项。
- 响应新增 `interpretation` 和可空 `clarification_id`。`needs_clarification` 携带最多两个问题，候选与证据为空；确认后使用实际生效的条件进行检索、过滤和推荐。
- 错误新增 `SESSION_EXPIRED`、`STALE_CLARIFICATION`（409）及 `INVALID_CLARIFICATION`（422）。会话和答案不匹配时拒绝，不能悄悄回退。
- Pydantic → JSON Schema / OpenAPI → TypeScript 生成链路保留。当前为 `0.1.0` 增量候选，合并前仍需 Y00/Y02 和主审共同确认版本、字段及会话归属。
