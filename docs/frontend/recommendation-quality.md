# 推荐质量与后端方向

原开发计划的方向仍然合理：理解本次需求，从可信片库或片单召回，硬条件过滤，按内容与偏好排序，给出少量有区别、可核对的候选，再接收反馈。计划已提出标签/关键词、可解释排序和多样性，无需推倒重写；当前缺口主要是数据与落地程度。工具调用成功和界面好看都不能证明选片更准。

## 本次补齐

默认池从单一总榜扩大为总榜、喜剧、剧情去重聚合；本次实际得到 240 部，不是固定清单。心情先按类型交叉筛选，再读取来源简介中的有限关键词线索；均衡排序同时减少类型和导演重复。轻松/治愈场景降低恐怖、沉重线索的优先级。关键词可能漏判或误判，权重尚未做偏好标定；没有协同过滤、向量模型或模型情感分析。

年代、时长、排除身份始终是硬条件；排序不会放宽它们。支持切回来源顺序，便于比较规则效果。“这次不想看”在当前页面会话的后续请求中持续生效，可撤销；刷新清空，不暗中建立用户画像。导演、美国内容分级按来源显示，缺失评分保持缺失。

冻结用例验证：轻松内容线索优先于有恐怖线索的高位项、前三部类型与导演多样性、排序稳定且不改写元数据；另有服务端硬条件和四组合浏览器流程验收。这些只验证规则契约，不构成“比豆瓣更准”的证据。

## 仍限制推荐价值的缺口

| 缺口 | 对用户的影响 | 优先补齐方式 |
| --- | --- | --- |
| 推荐来自美国区当前分类榜单 | 中文片名、冷门片、华语片及旧片覆盖不足 | 接入具有明确使用授权、稳定更新与中文别名的更广片库；不能拿固定样例充数 |
| 真实商店搜索返回零部电影 | 榜外经典片检索尚未可用；当前只能退回真实榜单标题检索 | 保留失败证据并检查供应方支持情况；未验证前不宣传全片库检索 |
| 没有可信评分、评论聚合和评价样本量 | 无法区分热销、争议作品与高口碑作品 | 接入有来源、时间和样本量的口碑信号，保留各来源，不自造或混合评分 |
| 心情只靠类别和简介关键词 | “治愈”“轻松”等主观标签不够稳定 | 建立经人工审阅的内容标签与避雷标注，处理否定、语境与未知；使用固定场景集回归 |
| 反馈只在当前会话 | 多次使用不会逐渐认识用户 | 在明确同意后记录看过、喜欢、不喜欢及排除原因，允许查看和删除 |
| 本地播放渠道未知 | 推荐影片不代表今晚在所在地可播放 | 单独接入带地区和更新时间的可播放数据，未知继续显示未知 |

## 下一阶段质量门槛

先固定一组包含零输入、轻松、治愈、约会、家庭、短片长、经典片、冷门偏好及冲突条件的人工审阅场景；为候选标注相关性、明显不适合项和可核对依据。与来源顺序基线用同一片库、同一时间快照比较前三项相关性、候选差异、硬条件违规率、选定所需轮次与来源缺失率，再调权重。没有真实交互数据前不采用协同过滤；没有人工标注和用户反馈前不承诺主观提升百分比。

这批数据和用户研究尚未完成。当前验收证明功能、来源和规则执行可靠，不能代替内容质量、实际喜爱程度或商业发布验收。
