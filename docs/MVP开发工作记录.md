### 如何判断成功或失败

| 输出或报告状态 | 含义及下一步 |
|---|---|
| `passed: true`（JSON中可能为小写true） | 本次模型解析符合E02；记录日期、实际模型与结果后，M03才有真实验证依据 |
| `NOT_CONFIGURED` | .env缺少某项，或文件名/位置不正确；检查根目录.env及三个字段 |
| `http_401` | 认证失败；检查是否复制完整、是否为实际有效API Key |
| `http_402` | 余额不足；到开放平台查看余额和额度后再测试 |
| `http_429` | 请求受到限流；查看平台状态，稍后在有上限的情况下重试 |
| `http_400` / `http_404` | 检查基础地址、模型名及账号支持情况；不要在基础地址重复填写接口路径 |
| `timeout` / `network_error` | 未取得成功响应；检查网络，不把失败当作解析通过 |
| `truncated` | 输出被截断，不算通过；记录结果再调整参数，不反复盲目重跑 |
| `empty_content` / `invalid_output` | 没有完整合法结构；需要检查适配或提示词 |
| `semantic_mismatch` | 输出结构合法，但动作或条件与预期不同，需要修复后复测 |
| `not_run_budget` | 选择的用例超过本次调用上限，后续用例没有执行 |

退出码0表示所选用例全部通过，1表示未全部通过，2表示未启用联网或配置无效/不完整。报告包含请求与响应模型名、结束原因、耗时和可取得的token用量；缺失用量和实际费用保持未知。

只需要分享脱敏结果，不需要分享密钥。报告不保存用户原文、原始模型回答、内部推理或上游错误正文。
