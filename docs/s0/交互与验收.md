# S0交互规格与验收

负责人A。可运行线框：启动Mock后打开`http://127.0.0.1:8000/`；实现文件为`web/s0/index.html`，无需构建依赖。S1再迁移到React组件。

## 页面结构

页面从上到下：观影意图输入→三个入口切换→候选/澄清/失败区→同屏对比→联调原始JSON。桌面卡片并排，小屏自动单列。原型保留S0模拟标识，产品实现时联调控制项移入开发环境。

| 入口/状态 | 触发与观察 | S0覆盖 | 后续实现 |
|---|---|---|---|
| 不知道看什么 | 输入心情、题材或时长 | 输入框及固定卡片响应 | C解析条件并生成真实候选 |
| 从我的片单选 | 粘贴片名/年份 | 文本区域、固定已确认合成ID | B持久化/消歧，C范围约束 |
| 已知道片名 | 搜索“春日来信” | 返回两个年份，展示需确认 | 选择确认后跳详情/对比 |
| ready | 选择“成功卡片” | 标题、片长、理由、局限及未知渠道 | 安全来源链接和完整评分组件 |
| needs_clarification | 选择“需要澄清” | 显示问题与选项 | 选项回传和累计轮数控制 |
| empty | 选择“无匹配” | 显示约束不足，未自动放宽 | 可编辑条件后重新查询 |
| degraded/timeout | 选择降级或超时 | 显示可恢复提示和错误JSON | 部分候选/缓存与重试交互 |
| unconfigured | 选择“未配置数据源” | 明示未配置 | 真实配置检查对接 |
| 反馈/记忆 | 点击“今天不想看”或查看记忆开关 | 仅当前页面视觉反馈，记忆开关禁用 | S3反馈幂等、确认、撤销、删除 |
| 对比 | 查看两部固定合成片 | 固定表格，缺失评分显示“未取得” | 选择2–3部动态对比 |

S0原型使用固定CN fixture，切换地区时会提示fixture不随地区变化，避免让联调误认为地区检索已生效。原型文字和输入通过textContent渲染，不插入模型/用户HTML。

## A的验收清单

- 三入口可以切换，输入标签与提示同步变化。
- 页面初始、加载、结果、澄清、空结果和接口错误都有明确状态。
- 卡片不自动播放视频，不展示剧情、结局或合成来源的“真实可点击”承诺。
- 多年份影片显示年份；未知渠道和评分不显示成不存在或零分。
- 手机宽度不会遮住输入或按钮，对比表可横向滚动。
- 键盘可聚焦控件，状态区域有aria-live，入口暴露选中状态。

本轮自动检查覆盖HTML可服务及Mock响应，不代表已执行浏览器视觉/移动端验收。三人评审和浏览器实测应记录在[验收记录](验收记录.md)。
