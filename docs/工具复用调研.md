# 工具复用调研与选型

核查日期：2026-10-15。方法：读取下列官方文档/仓库许可页面，检查用途与限制；未安装、未压测、未使用私有Key验证接口、未实测大陆连通性。页面可读不等于API可用，库许可不等于数据/模型权重许可，开源不等于部署零成本。

## 1. 推荐最小组合

| 能力 | 现成工具及本次证据 | 决定 | 成本/限制与下一步 |
|---|---|---|---|
| 影片身份、详情、基础筛选 | TMDB API：Discover支持多类筛选，包括genres、keywords、时长等；FAQ说明非商业用途在署名条件下可免费使用 [R1/R2] | P0主候选，不自建电影百科 | 需要Key和署名；商业用途需洽谈许可；中文长尾字段/地区覆盖需S0验证 |
| 流媒体渠道 | TMDB Watch Providers，数据来自JustWatch，按国家返回提供商；官方明确不返回完整内容深链 [R3] | 用作补充，不承诺中国大陆完整片源 | 要注明JustWatch；可链接提供的TMDB页面。大陆覆盖/数据时效待验证；不是购票/票价API |
| 合法信息检索 | Tavily Search API，官方文档有域名过滤、搜索深度、raw content等选项 [R4] | 可选证据检索适配器；不是先决依赖 | 需另查当前套餐/配额并获预算；搜索可见不代表有转载全文权，不能保证豆瓣/小红书可访问 |
| 工作流/状态编排 | LangGraph，支持可预测步骤与模型步骤混合、持久化等；仓库MIT [R5/R6] | P0后半使用有边界图，复用状态编排，不手写ReAct引擎 | checkpoint与长期画像分开；框架不会自动解决授权、记忆准确或API成本 |
| API与数据校验 | FastAPI、Pydantic，仓库MIT；FastAPI官方支持pytest/TestClient，底层HTTPX [R7–R9] | P0采用 | 复用验证/文档/测试客户端；个人数据权限仍需业务设计 |
| 数据持久化 | SQLite，官方说明public domain [R10] | P0采用，暂不上独立向量服务 | 备份/加密/文件权限需配置；多实例写入再评估PostgreSQL |
| 基础文本相似度 | scikit-learn TF-IDF，库BSD-3-Clause [R11/R12] | P0有需要时直接复用 | 中文需适当分词或字符n-gram；不是语义理解的充分替代 |
| 语义检索 | SentenceTransformers，库Apache-2.0 [R13/R14] | P1按评估结果引入 | 模型权重、训练数据条款单独核查；下载、内存/CPU和多语效果均有成本 |
| 自动测试 | pytest MIT，Playwright Apache-2.0；HTTPX BSD-3-Clause [R15–R18] | P0采用；HTTP层先用MockTransport而非新增Mock服务 | UI浏览器依赖须安装；默认测试不连真实LLM/API |
| Web界面 | React、Vite，仓库MIT [R19/R20] | P0采用常规组件，不自研渲染/打包器 | 前端鉴权、可访问性、API错误显示仍需测试 |

LLM供应商暂不锁定：用统一适配器隔离结构化输出、超时和费用统计；先用Fake完成规则测试，再用目标部署网络下的候选供应商做小样实测。未选定套餐前不声称某模型单次人民币成本。

## 2. 整体平台与推荐框架的取舍

| 候选 | 已核查事实 | 为什么不直接作为主应用 |
|---|---|---|
| Dify | 许可是修改版Apache-2.0，包含多租户服务及其前端Logo/版权条件 [R21] | 可做快速流程原型，但领域测试、细粒度偏好撤销和隐私隔离仍需代码；部署与许可复杂度未证明更低。不是简单“Apache任意商用” |
| Flowise | 普通部分Apache-2.0；enterprise目录及明确标记文件另有商业许可 [R22] | 适合可视化实验，但本项目要让可测业务规则成为核心；不为少量工具引入整套服务 |
| RecBole | 已有推荐算法框架，MIT [R23] | 当前没有足够合法用户-影片交互数据；先不训练协同过滤，未来有数据且内容基线不足再用它，不重写算法训练器 |
| 独立向量库/Memory服务 | 本轮不做专项测评，不据印象确认许可或免费套餐 | P0仅结构化偏好和小片库，SQLite足够；额外服务会增加迁移、权限和删除同步成本 |

结论：复用成熟的API/框架/测试库，自写与需求直接相关的约束、证据绑定、偏好语义和降级策略。现成整套推荐/Agent平台不一定比轻量集成更省总成本。

## 3. 数据源红线与未知项

### 豆瓣、社交影评与导入

本次尝试访问旧豆瓣电影开发文档地址超时 [R24]。这只能说明本次未验证成功，**不能推断豆瓣一定没有API，也不能当作拿到开放授权**。上线前需要重新确认有效文档、申请方式、实际权限及条款。

P0不依赖自动登录豆瓣或批量抓取影评。先支持手动片单与用户授权材料；P1兼容已验证的用户文件格式。没有验证官方导出能力前，不写“一键导入豆瓣官方评分”。不索要账号密码、Cookie，不绕过验证码/付费墙/访问限制。

搜索结果摘要只作检索线索或明确标注的片段；未打开全文不能称已读全文、未取得多源不能称全网共识。豆瓣、小红书、公众号全文的使用与存储各自需授权判断，点赞量不等于真实性。

### 中国大陆片源与院线

TMDB/JustWatch文档证明存在国家维度渠道接口，但本次没有证据证明中国大陆具体覆盖及准确率。猫眼、淘票票、地图、电商、私密社群接口本轮未验证，不列作已可接入工具。

没有可靠影片级链接时，可以提供明确标注的平台搜索入口，用户自行查验；这不算“已找到可播放片源”。购票平台首页也不等于该片当前有场次。取景地地图与影院距离筛选是不同需求，不能因为用户嫌影院少就优先做电影打卡地图。

## 4. S0工具可行性实验

1. 选约30部人工核验的小样影片，覆盖中文同名、翻拍、冷门题材、旧片/新片、不同地区；得到ID、年份、时长和关键标签的参考答案。规模是验证预算，不是全面覆盖证明。
2. 用申请到的TMDB Key验证：实体识别、中文/英文别名、核心字段缺失率、长尾需求匹配支撑、部署地区网络时延。结果逐项保存，不只“接口200”。
3. 对上述影片按目标观看地区验证渠道：支持哪些地区、未知比例、更新/过期行为、是否只有聚合页。中国大陆无数据就标明，不能借其他地区冒充。
4. 对10部有授权或合法可访问评价的影片，核查来源可达率、独立来源数、观点能否溯源、低剧透摘取可行性；搜索摘要/全文分别记账。
5. 记录第三方许可、署名位置、缓存/再分发限制、API配额、当前套餐和预计调用量；条款页无法核实的项目不得当“已批准”。
6. 出具通过/条件通过/不可用清单：能支撑哪些P0体验？哪些只能手工演示？若核心核验数据缺失，向用户报告范围影响后再确定“实时聚合”路线。

工程探索允许先做小实验，但产品实现仍遵循先写适配器契约和期望结果，再接真实工具。手工整理数据和Fake仅用于验证，不冒充实时能力。
